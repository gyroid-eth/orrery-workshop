# Fresh-install trial records

No exercise trial results have been recorded here. Every current prompt is **Not yet tested on a fresh install**. Installation, authentication, Mail, child startup, and useful collaboration must be tested separately from static documentation checks.

Copy the template below to a new record after an actual run. Use generic environment labels; redact tokens, personal paths, account details, and private inputs. Record both success and failure. A browser demo is not a fresh local installation.

```markdown
# Trial: <exercise> — <date>

## Environment
- OS / version:
- Fresh install or existing configured environment:
- WSL2 distro and Linux CLI location, if applicable:
- ORRERY / Telemetry commit or version:
- Claude Code / Codex CLI versions:
- Authenticated providers and actual models (unknown if unverified):
- Working directory type: empty workshop folder / public demo vault
- Prompt file and repository commit:

## Run
- Install/check outcome:
- Start/end and elapsed time:
- Human interventions and time waiting for them:
- Expected collaborators vs actually launched:
- First ready messages observed:
- Mail evidence: sender, recipient, subject, IDs if available (no private content)
- Direct peer handoffs observed:
- Output path, described generically:
- Writer/checker separation and actual provider pairing:
- Checks performed on the output:
- Did the intended cooperation happen? yes / partial / no, with evidence

## Stalls and fixes
- Exact failed step or error, redacted:
- Fix or workaround:
- Remaining unverified behavior:
- Whether a changed prompt was rerun:

## Cleanup
- Agents selected for EXIT:
- Process stop confirmed:
- Unrelated agents left untouched:
```

Start with [shiritori](../play/shiritori.md), then the paper exercise and optional games. For Windows, record a fresh WSL2 Ubuntu installation rather than assuming behavior from macOS. Do not replace missing evidence with plausible dialogue or mark output reviewed when its checker failed to start.
